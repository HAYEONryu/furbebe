# 실제 원문 기반 태그 재구성 검토

분석일: 2026-09-22. 생성 규칙, DB 태그, 프런트엔드 동작은 변경하지 않았다.

## 데이터 범위

- 기존 DEV PostgreSQL 데이터를 읽기 전용 트랜잭션으로 조회했다. 신규 원천 API 수집이나 프런트엔드 DB 연결은 수행하지 않았다.
- 전체 7,290마리: 개 4,619, 고양이 2,515, 기타 156. 아래 후보 수치는 **개 4,619마리** 기준이며 종료된 공고도 포함한다. 보호중인 개는 3,115마리다.
- 데이터의 `last_seen_at` 범위는 2026-09-15 23:28:29~23:29:03 UTC, 한국 시각으로 9월 16일이다. 9월 22일 현재 원천 데이터 전체를 의미하지 않는다.
- 분석 필드는 원문 `specialMark`, `sfeSoci`, `sfeHealth`. 각각 정규화된 `special_mark`, `social_text`, `health_text`에 대응한다.

## 후보와 실제 빈도

아래 숫자는 세 원문 필드 중 검색식에 한 번 이상 걸린 **고유 개체 수**다. 부정·추정·시점·모순을 판정하기 전의 탐색 후보이며 실제 생성할 태그 수 또는 정확도 수치가 아니다. 후보 간에는 중복이 있다. 표의 예시는 실제 기록이다.

| --- | ---: | --- | --- |
| 온순·순함·얌전 | 1,533 / 1,009 | `온순함`, `순하고 착함`, `얌전함` | `온순해요` — 얌전함과 온순함은 규칙에서 구분 |

건강 묶음은 치료, 피부병, 피부질환, 파행, 골절, 심장사상충, 사상충, 심장병, 파보를 검색한 결과이며 모든 건강 기록을 포괄하지 않는다. 음성·예방·검사 언급도 포함하므로 질환 보유 개체 수로 해석하면 안 된다.

`sfeSoci`에도 `어미와함께 포획`, `들개무리`, 입양 홍보 문구가 들어 있다. 필드 이름만으로 성격 근거라고 간주하지 않는다. `sfeHealth`의 `건강상 큰 문제는 없어 보입니다…` 25건과 `양호` 14건도 건강 보장 태그로 바꾸지 않는다.

## 실제로 발견한 오분류 위험

- `온순하나 사람을 경계함`: 온순함과 사람 친화성은 별개다. `사람 좋아요`로 확장하지 않는다. 카드에서는 천천히 접근할 필요를 우선하고 상세에는 두 관찰을 함께 제공한다.
- `사람을 따르지않고 입질이 있음`: `사람`과 `따르` 검색만으로 긍정 태그를 만들면 반대 뜻이 된다.
- `사람대한 경계심 없음`: `경계심`만 검색하면 부정문을 뒤집게 된다.
- `반환예정, 순하고 사람을 잘따름.`: `예정`이 있다고 문장 전체를 제외하면 유효한 행동 기록도 사라진다. 부정·추정·시점은 해당 절과 대상에 연결해야 한다.
- `피학대견`: `대견` 부분 문자열 검색에 걸린다. 넓은 다른 개 관련 탐색 13건 중 긍정적 관계를 명시한 좁은 검색은 2건뿐이었다.
- `다른 개에게 물려…`: 다른 개를 언급했다고 개 친화적인 것은 아니다.
- 목줄·리드줄·하네스·산책을 합치면 483마리지만 `산책` 명시는 1마리다. 착용품을 산책 능력으로 바꾸지 않는다.
- `기본 배변훈련,사회성 좋음`: 훈련 언급을 배변 완벽 숙지로 바꾸지 않는다. `실외배변`도 실내 배변 성공과 다른 정보다.
- `사상충-양성, 접종(종합백신,코로나장염,광견병,스팟라인)`: 검사 결과와 접종 내역을 분리한다. `파보음성`, `사상충예방약복용`을 감염으로 해석하지 않는다.
- `잠복고환 추정`, `인대 손상의심`: 추정 표현을 확정 진단으로 바꾸지 않는다.
- `온순, 얌전, 겁있음.`: 얌전함은 상황에 따른 위축일 수 있으므로 `짖지 않아요`, `초보자에게 쉬워요`, `아이와 잘 지내요`로 확대하지 않는다.

## 권장 태그 구조와 노출

기존 FACT / VIBE / TRAIT 분류를 유지하면서 텍스트 관찰은 TRAIT에 근거와 함께 저장하는 방향을 권한다. 건강 기록은 행동 TRAIT와 분리해 상세의 기존 건강·돌봄 영역에서 먼저 보여 준다.

1. **FACT**: 체중 기반 크기, 털색, 출생연도·추정 나이. 나이는 기본 정보와 중립적인 필터에 유지한다.
2. **VIBE**: `콩만이`, `구름이`, `치즈` 같은 기존 외형 기반 별칭. 카드에서 `흰색`+`구름이`처럼 같은 근거를 중복 노출하지 않는다.
3. **TRAIT**: 우선 `사람 좋아요`, `애교쟁이`, `온순해요`, `활발해요`, `천천히 친해져요`. 문구가 명시적이고 충돌이 없는 경우에만 생성한다. 기록이 없으면 생성하지 않는다.
4. **건강·생활 기록**: 접종의 종류·차수·날짜, 검사 결과, 치료 상태, 산책·배변 관찰 등을 원문과 함께 상세에서 제공한다. 접종 일부 기록을 `접종 완료`로 뭉뚱그리지 않는다.

`어르신댕`은 추천 태그에서 제거하는 안을 권한다. 고령을 대표 별명으로 삼는 대신 실제 성격·교감 근거로 소개하고, 나이는 숨기지 않는다. `senior` FACT와 그 표시용 `senior_dog` VIBE는 분리되어 있으므로 나이 필터를 유지하면서 별칭만 제거할 수 있다. 고령을 `차분해요`, `산책이 편해요`로 자동 치환하지 않는다.

메인 빠른 탐색에는 품질 검증 후 `사람 좋아요`, `애교쟁이`, `온순해요`, `활발해요`, `천천히 친해져요`를 우선 후보로 삼는다. 명시적 산책·개 친화 기록은 현재 너무 적어 주요 필터보다 상세 정보가 적절하다. 카드 태그는 관찰 태그 1~2개 + 외형 별칭 1개 이내, 총 3개 이하를 권한다. 입질·공격 행동을 단순히 귀여운 낯가림 별칭으로 덮지 않고 상세 근거와 필요한 안내를 유지한다.

상세에는 예를 들어 `사람 좋아요` → `보호소 기록: “사람을 잘 따름”`처럼 출처를 보여 준다. 수집 시각과 실제 관찰 시각을 혼동하지 않고, 관찰 시각이 없으면 최신 관찰이라고 표현하지 않는다. 사용자가 확률로 오해할 confidence 표시는 하지 않는다. 전체 축종 목록을 유지하되 개 전용 문구·규칙을 고양이와 기타 동물에 무조건 적용하지 않는다.

## 규칙 구현 전 확인할 사항

- 공백·구두점 정규화 후 어절·절 수준의 패턴을 검사한다. `순`·`대견` 같은 짧은 부분 문자열만으로 분류하지 않는다.
- 행동 주체와 대상(사람/개/고양이), 긍정·부정, 추정, 시점, 같은 기록 내 충돌을 함께 평가한다. 모호하거나 충돌하면 자동 생성을 보류하고 원문을 유지한다.
- source field, 원문 근거 구간, 규칙 ID/버전, 수집 시각을 보존한다. 필드가 다르다고 중복 태그를 만들지 않는다.
- 대표 긍정 사례뿐 아니라 부정·혼합·추정·정형 문구를 포함한 수동 정답 표본으로 오탐을 검증한다. 이번 탐색 건수로 precision/recall을 주장할 수 없다.
- 승인 후 별도 범위에서 규칙과 fixture 테스트, 기존 `senior_dog` 정리 및 카탈로그 노출을 함께 설계한다. 현재 파일에서 생성 규칙을 수정하거나 새 Phase를 시작하지 않았다.

## 재현 자료

로컬 분석 자료는 git에 포함되지 않는 `.local/tag-research-20260922/`에 있다.

- `extract.py`: DEV 읽기 전용 추출. 연결 정보는 출력하지 않는다.
- `snapshot.json`: 분석에 필요한 원문과 개체/수집 정보만 담은 스냅샷.
- `explore.py`: 필드별 빈도와 원문 어휘 탐색.
- `analyze.py`: 탐색 정규식, 개체 단위 집계, 반례 탐색.
- `analysis.json`: 패턴별 전체/보호중/필드별 집계. 분석 스크립트 실행으로 재생성할 수 있다.

위 스크립트는 탐색 도구이며 운영 태그 판정기로 사용할 수 없다. 이 문서는 현 DEV 표본에 대한 검토이며 원천 데이터 전체의 분포를 추정하지 않는다.
