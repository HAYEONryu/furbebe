## animals_active 정의 가능 여부

**snapshot에 processState=보호중으로 기록된 수는 계산할 수 있다.** 전체 7,011건, 개 5,098건이다. 그러나 이를 제품의 **지금 입양 가능한 수** 또는 검증된 **활성 동물 수**라고 부를 근거는 부족하다.

- 검토 표본 #21의 “입양완료(09/01 전산처리예정)”는 실제 `processState=종료(입양)`이다. 상태 충돌 사례로 잘못 보고하지 않는다. 텍스트에 과거 처리 안내가 남아 있다는 근거로만 사용한다.
- 기존 사용자 표시 정책은 **보호중 AND 공고 시작 후 10일 이상 → 입양 가능 표시**다. 2026-09-15 기준 개 3,909건이 해당하며 1,189건은 보호중으로 남는다. 이 표시를 upstream 상태나 보호소의 입양 확정으로 해석하지 않는다.
- `updTm`의 시간대·업무상 상태 갱신 보장까지 확인되지 않아 snapshot 이후 실제 상태를 보증하지 못한다.

## 추천 UX

1. 체중 범위·출생연도·지역·원문 상태처럼 설명 가능한 정보로 기본 탐색을 구성한다.
2. 행동 정보는 **근거가 있고 검토를 통과한 경우에만 선택 제공**하는 방향을 추천한다. 45.88% 후보율만으로 성격 태그를 기본 탐색의 필수 조건으로 삼지 않는다.
3. 상세 화면에서는 출처 필드·관찰 표현·시점을 함께 보여주는 “보호소가 기록한 특징” 영역을 검토한다. 근거가 없으면 “정보 없음”을 유지한다. 성격을 추론하거나 다른 유형의 태그로 빈 정보를 채우지 않는다.
4. 건강 정보는 행동과 별도 영역에서 원문 근거를 보여준다. **양성/음성, 예방/치료, 추정/확정, 과거/현재**를 구분할 수 있을 때만 해석한다. 새 진단을 만들지 않는다.
5. 행정 문구와 입양 절차 안내는 성격 근거에서 구분한다. “behavior 후보 있음”을 “친화적임”으로 바꾸지 않는다.

**사용자 결정 필요:** v1에서는 근거 있는 설명을 선택 제공하고, production 성격·건강 태그 정책은 사람 검토 후 별도로 결정하는 방향을 채택할지. 운영 규칙·enum·모델은 만들지 않았다.
