# 태그 생성 규칙 — TRAIT 3.0 / VIBE 2.0

Phase 8.5에서 행동·성격 생성기를 `rules/3.0`으로 전환했다. 기존 VIBE 생성 규칙은
`rules/2.0`을 유지하며 기존 FACT/VIBE를 TRAIT 재생성에서 수정하지 않는다.
최신 결정과 검증 결과는 [Phase 8.5 보고](phase8-5-behavior.md)를 참조한다.

사용자 지시에 따라 사람 검토 완료를 **가정하여 진행**했다. 개별 정답 라벨이 없어
실측 TP/FP/FN·precision은 미측정이다. 아래 채택은 사용자 승인과 원문에 있는 명시적 표현에
근거한 보수적 선택이며, 측정된 precision 보증을 뜻하지 않는다.

## 입력과 근거

| 원천 필드 | 정규화 필드 | 사용 |
| --- | --- | --- |
| `specialMark` | `special_mark` | 행동, 외형·색상 보조, 안전 정보 |
| `sfeSoci` | `social_text` | 행동, 외형 보조, 안전 정보 |
| `adptnTxt` | `raw_payload.adptnTxt` | 명시적 행동 설명. 입양 행정 문구는 차단 |
| `sfeHealth` | `health_text` | 건강 원문 보존. **TRAIT 입력에서 제외**. 기존 외형/안전 처리 유지 |
| `colorCd` | `color_text` | 색상/무늬 우선 근거 |
| `weight` | `weight_kg` | 현재 몸집 |

건강·성별·나이·접종 태그나 의료 진단을 새로 생성하지 않는다. 건강 원문은 상세에 유지한다.
한 동물에게 TRAIT가 없어도 정상이다. 색상이나 몸집으로 성격을 추측하지 않는다.

## 채택 TRAIT — 5개 태그, 6개 규칙

| 표시 | key | rule_id | 명시적 근거 예 |
| --- | --- | --- | --- |
| 순딩이 | `gentle` | `gentle-explicit-v3` | 온순, 순함, 순하고, 순한 성격 |
| 소심요정 | `shy` | `cautious-explicit-v3` | 겁 많음·있음, 소심, 경계심 있음·많음·강함 |
| 똥꼬발랄 | `playful` | `active-explicit-v3` | 활발, 활동적 |
| 차분선비댕 | `calm` | `calm-explicit-v3` | 얌전, 차분 |
| 사람좋아 | `people_friendly` | `people-like-v3` | 사람을 좋아함, 사람 손길을 좋아함 |
| 사람좋아 | `people_friendly` | `people-follow-v3` | 사람을 잘 따름 |

실제 정규식은 [behavior.py](../backend/jobs/animal_sync/tagger/behavior.py)에 있다.
`cautious`/`active`라는 의미를 기존 key인 `shy`/`playful`에 대응시켜 API 호환성을 유지한다.
두 사람좋아 규칙이 동시에 맞아도 태그는 한 번만 저장하며 앞 규칙의 근거를 선택한다.

### 차단 조건

1. 원문 필드와 문장 경계를 유지한다. 공백 제거는 매칭에만 사용한다.
2. 쉼표는 문장 경계로 나누지 않아 공동 부정을 보수적으로 검사한다.
3. 부정·불확실·행정·일시적 의료 상황이 있는 문장은 제외한다.
4. 다른 문장/필드에서 같은 성격을 부정하거나 불확실하게 설명하면 해당 태그를 보류한다.
5. 원문 문장 그대로 `출처: 문장` 형식으로 저장한다.

| 입력 | TRAIT 결과 |
| --- | --- |
| `사람을 좋아하지 않음` | 없음 |
| `산책 중 발견`, `산책을 좋아함` | active 생성 안 함 |
| `사람을 경계하지 않음` | 소심요정·사람좋아 모두 생성 안 함 |
| `온순, 얌전하지 않음` | 공동 부정으로 보류 |
| `얌전한 성격으로 추정`, `마취 후 차분함` | 없음 |
| `활발한 입양 홍보`, `온순한 보호자 희망` | 없음 |
| `온순함. 피부질환 있음.` | 순딩이. 건강 문장은 성격 근거로 사용 안 함 |
| `사람을 좋아함. 사람을 좋아하지 않음.` | 상충하여 보류 |

문장 전체 차단으로 일부 올바른 근거도 놓칠 수 있다. coverage보다 precision을 우선한다.
정규식이 모든 자연어 부정·인용·주체를 이해한다고 보장하지 않는다.

### 보류한 규칙과 태그

`people-approach-v3`, `affection-explicit-v3`, `lap-explicit-v3`는 100건 표본에서 양성
후보가 0건이어서 비활성으로 유지한다. 발라당은 후보 검사에서 애교쟁이에 대응하고,
무릎 선호는 무릎댕댕이라는 표시명을 유지하지만 현재 자동 생성에는 포함하지 않는다.
호기심·지능·예민함·적극성·다른 개 친화성·미소 등의 v2 TRAIT도 현재 생성하지 않는다.
`clingy`를 사람 친화성에서 추론하지 않는다. 수동 배정과 태그 사전 key는 보존한다.

## VIBE — 기존 2.0 규칙 유지

### 대표 색상/무늬 — 최대 한 개

**그레이 계열이 포함되면 색상 태그 없음**이 우선한다. 회색·실버·청회색·그레이가
다른 색/패턴과 섞여도 흰둥이나 검댕이로 분류하지 않는다.
`color_text`를 우선하고, 인식 불가일 때만 `special_mark`의 색상 표현을 사용한다.
그레이 판정을 보조 원문으로 덮어쓰지 않는다. 의료·오염·목줄 문맥은 보조 근거에서 제외한다.

| 우선순위 | 표시 / key | 조건 |
| --- | --- | --- |
| 1 | 삼색이 / `patterned_coat` | 세 색상 계열 이상 또는 반점·얼룩·호피·브린들 |
| 2 | 쿠앤크 / `cookies_cream` | 검정+흰색 두 계열 |
| 3 | 브라우니 / `brownie` | 갈색·밤색·황갈색·흑갈색·탄·금색·레몬색·주황. **연갈색·옅은 갈색 포함** |
| 4 | 크림이 / `cream_coat` | 크림·베이지·연베이지·옅은 황색·연한 황색 |
| 5 | 검댕이 / `black_coat` | 검정 계열만 인식 |
| 6 | 흰둥이 / `white_coat` | 흰색 계열만 인식 |
| 해당 없음 | 태그 없음 | 그레이 포함 또는 인식 가능한 색상/패턴 없음 |

긴 색상어를 먼저 인식한다. `흑갈색`은 갈색 한 계열이며 `흰색&갈색&탄`은 두 계열이다.
정확한 목록은 [colors.py](../backend/jobs/animal_sync/tagger/colors.py)에 있다.

### 외형 보조

| 표시 / key | 명시적 표현 |
| --- | --- |
| 곱슬몽실 / `curly` | 곱슬 |
| 쫑긋귀 / `pointed_ears` | 쫑긋 |
| 꼬리콥터 / `wagging_tail` | 꼬리 흔듦·살랑·꼬리치며 |
| 복슬복슬 / `fluffy` | 복슬·복실·복슬복슬·복실복실·풍성한 털/털숱 |

곱슬과 풍성함의 근거가 각각 있으면 함께 표시한다. 단순 장모·긴 털로 복슬복슬을 추론하지 않는다.
`털이 풍성하지 않음` 등 부정은 제외한다. 팔랑귀·무릎친구·발라당이라는 독립 태그는 없다.

### 현재 몸집 — 최대 한 개

| 현재 kg | 표시 / key |
| --- | --- |
| 0 이상 5 미만 | 쪼꼬미 / `pocket` |
| 5 이상 10 미만 | 품에쏙 / `cuddly` |
| 10 이상 20 미만 | 댕든든 / `sturdy` |
| 20 이상 | 왕크왕귀 / `giant` |

누락·음수·비정상 값은 생성하지 않는다. 성견의 예상 체중이나 크기를 추론하지 않는다.
기존 size_group 탐색 필터의 범위는 별도 정책이며 변경하지 않는다.

## 안전 배지와 표시

입질·물려고 함·으르렁은 `bite_caution`(입질주의), 공격성·사나움·매우 강한 경계는
`strong_guarding`(강한경계) 배지다. 부정 표현은 제외한다. 태그 대신 API `safety_badges`로
기존 원문에서 조회 시 계산하며 태그 개수 제한에 포함하지 않는다.

사전은 [catalog.py](../backend/jobs/animal_sync/tagger/catalog.py)에 27개 key를 정의하지만
자동 TRAIT는 채택한 5개만 생성한다. 카드에는 성격·관계 최대 두 개, 색상 한 개를 표시하며
색상이 없으면 몸집을 사용한다. 외형 보조는 상세에 표시한다. 건강 원문도 상세에 유지한다.
기존 사전에만 있는 FACT/VIBE 및 수동 태그의 표시를 이 단계에서 비활성화하지 않는다.

## 저장·버전·재생성

TRAIT에는 `evidence`, `rule_id`, `confidence`, `generator`, `generator_version`이 모두 저장된다.
`rules/3.0` TRAIT confidence `0.90`은 휴리스틱 점수이며 실측 precision이나 확률이 아니다.
VIBE는 `rules/2.0`이다. 스키마 변경 없이 기존 테이블을 사용한다.

일반 sync는 원문이 같아도 채택 TRAIT를 재계산한다. 알고 있는 자동 TRAIT의 1.0/2.0 기록을
3.0으로 교체하고, 근거가 사라지거나 규칙이 보류되면 자동 배정만 제거한다.
수동·다른 생성기·알 수 없는 버전/키와 FACT/VIBE는 TRAIT 경로의 삭제 대상이 아니다.
일반 sync의 VIBE 갱신은 기존 2.0 경로에서 독립적으로 처리한다.

TRAIT만 DEV에서 재생성:

```powershell
.venv/Scripts/python.exe -m backend.jobs.animal_sync.behavior_retag --database-target supabase-dev
.venv/Scripts/python.exe -m backend.jobs.animal_sync.behavior_retag --database-target supabase-dev --apply
```

기본 명령은 읽기 전용 예상 분포다. `--apply`는 채택 규칙을 두 번 적용하여 멱등성과
보존 지문을 확인한 뒤 commit한다. `--verify`는 모든 후보를 시험한 후 롤백하는 별도 모드다.
production 대상은 지원하지 않는다. 기존 전체 `retag`는 VIBE도 갱신하므로 Phase 8.5 DEV 작업에 사용하지 않는다.

## 검토 지표

사람 정답란을 자동 예측으로 채우지 않는다. [평가 도구](../backend/jobs/animal_sync/behavior_review.py)는
100개의 명시적 정답이 제공되면 tag/rule별 TP·FP·FN·precision을 계산한다.
예측 0건의 precision은 `null`이며, 같은 태그를 여러 규칙이 찾아도 tag 지표에서 중복 계산하지 않는다.
현재 수치는 미측정이다. 100건은 순차 층화 표본이므로 모집단 recall의 정확한 추정치로 사용하지 않는다.
